# Schema — Wiki 規範與模板

## 概述

本文定義了 LLM Wiki 的結構、頁面模板、欄位規範，確保 wiki 保持一致性和可維護性。

---

## 核心原則

1. **一致性** — 所有頁面遵循相同的結構和 frontmatter 格式
2. **可追蹤性** — 每個頁面記錄來源、修改時間、狀態
3. **互連性** — 頁面之間透過雙向連結建立網絡
4. **可讀性** — 使用清晰的標題層次和視覺分隔

---

## Frontmatter 規範

每個 wiki 頁面必須以 YAML frontmatter 開頭：

```yaml
---
title: 頁面標題（必須）
tags: [tag1, tag2, tag3]  # 最多 5 個標籤（可選）
source: 來源檔名  # 例如 llm-wiki-karpathy（必須）
date: 2026-06-17  # Ingest 日期（必須）
status: published  # published 或 draft（必須）
version: 1  # 修訂版本（可選）
---
```

**欄位說明**：

| 欄位 | 類型 | 必須 | 說明 |
|------|------|------|------|
| `title` | string | ✓ | 頁面標題，與檔名一致 |
| `tags` | array | | 最多 5 個標籤，用於分類和搜尋 |
| `source` | string | ✓ | 原始來源檔名（用於追蹤和去重） |
| `date` | YYYY-MM-DD | ✓ | Ingest 或修改日期 |
| `status` | string | ✓ | `published` 最終版；`draft` 草稿 |
| `version` | number | | 修訂版本，初始為 1 |

## 頁面模板

### 1. 來源摘要頁（Source Summary）

用於摘要單一來源的主要內容。

**命名**：`[來源名]-摘要.md`  
例如：`llm-wiki-karpathy-摘要.md`

**模板**：

```markdown
---
title: [來源名] 摘要
tags: [主題, 摘要]
source: [來源檔名]
date: 2026-06-17
status: published
---

# [來源名] 摘要

## 核心主張

- 要點 1
- 要點 2
- 要點 3

## 主要章節

### 章節 1
說明...

### 章節 2
說明...

## 關鍵概念

| 概念 | 定義 |
|------|------|
| 概念 1 | 解釋 |
| 概念 2 | 解釋 |

## 對本 Wiki 的啟示

- 應用 1
- 應用 2
- 應用 3

## 參考

- [[相關概念 1]]
- [[相關概念 2]]
```

### 2. 概念頁（Concept Page）

單獨解釋一個重要概念。

**命名**：`[概念名].md`  
例如：`LLM 基礎.md`、`提示詞設計.md`

**模板**：

```markdown
---
title: [概念名]
tags: [分類, 子類]
source: 綜合自 [來源列表]
date: 2026-06-17
status: published
---

# [概念名]

## 定義

簡潔定義和背景說明。

## 核心要素

### 要素 1
說明...

### 要素 2
說明...

## 實踐應用

- 應用場景 1
- 應用場景 2

## 常見誤區

- 誤區 1：解釋為什麼這是誤區
- 誤區 2：解釋為什麼這是誤區

## 相關頁面

- [[上位概念]]
- [[下位概念 1]]
- [[下位概念 2]]
- [[關聯概念]]
```

### 3. 實體頁（Entity Page）

記錄人物、工具、模型等具體實體。

**命名**：`[實體名].md`  
例如：`GPT-4.md`、`Andrej Karpathy.md`

**模板**：

```markdown
---
title: [實體名]
tags: [類型, 領域]
source: 綜合自 [來源列表]
date: 2026-06-17
status: published
---

# [實體名]

## 基本信息

| 屬性 | 內容 |
|------|------|
| 類型 | [類型] |
| 出現時間 | [時間] |
| 開發者 | [開發者] |
| 相關連結 | [連結] |

## 概述

簡短介紹。

## 主要特點

- 特點 1
- 特點 2
- 特點 3

## 應用與影響

說明其在領域中的角色和影響。

## 相關資源

- [[相關概念 1]]
- [[相關工具]]
```

### 4. 比較頁（Comparison Page）

比較多個相似的事物。

**命名**：`[對比主題]-比較.md`  
例如：`LLM-vs-傳統NLP.md`

**模板**：

```markdown
---
title: [對比主題] 比較
tags: [分類, 對比]
source: 綜合自 [來源列表]
date: 2026-06-17
status: published
---

# [對比主題] 比較

## 比較維度

| 維度 | [項目 1] | [項目 2] | [項目 3] |
|------|---------|---------|---------|
| 特性 1 | ... | ... | ... |
| 特性 2 | ... | ... | ... |
| 特性 3 | ... | ... | ... |

## 詳細分析

### 相似之處
- 相似 1
- 相似 2

### 差異之處
- 差異 1
- 差異 2

## 應用場景

### 適用 [項目 1] 的情況
- 場景 1
- 場景 2

### 適用 [項目 2] 的情況
- 場景 1
- 場景 2

## 相關頁面
- [[相關概念]]
```

### 5. 工作流程頁（Workflow Page）

記錄複雜的流程或步驟。

**命名**：`[流程名]-流程.md`  
例如：`LLM-Wiki-工作流程.md`

**模板**：

```markdown
---
title: [流程名] 流程
tags: [流程, 工作方法]
source: 綜合自 [來源列表]
date: 2026-06-17
status: published
---

# [流程名] 流程

## 整體流程

```
[第一步] → [第二步] → [第三步] → [結果]
```

## 步驟詳解

### 第一步：[步驟名]
**目的**：達成什麼
**方法**：
1. 子步驟 1
2. 子步驟 2

**輸出**：什麼結果

### 第二步：[步驟名]
...

## 關鍵決策點

- 決策 1：何時選擇路徑 A vs B
- 決策 2：如何判斷品質

## 常見陷阱

- 陷阱 1：如何避免
- 陷阱 2：如何避免

## 相關頁面
- [[相關概念 1]]
- [[工具 1]]
```

## 標籤規範

使用標籤分類頁面，便於檢索。建議使用以下主類別：

| 主類別 | 說明 | 範例子標籤 |
|--------|------|----------|
| `概念` | 抽象的想法 | 架構、演算法、理論 |
| `工具` | 軟體、框架 | Python、Framework、API |
| `方法` | 實踐方法 | 提示詞、訓練、部署 |
| `實體` | 人物、組織 | 人物、公司、研究機構 |
| `應用` | 實際應用 | 文本生成、分類、推薦 |
| `摘要` | 來源摘要 | 論文、文章、書籍 |

## 連結規範

### 內部連結

使用 Obsidian 格式的雙方括號：

```markdown
[[頁面名]]          # 簡單連結
[[頁面名|顯示文字]]  # 自定義顯示文字
```

### 雙向連結

- **反向連結**：在相關頁面中用 `## 參考` 或 `## 相關頁面` 段落列出反向連結
- **自動新增**：lint 操作會自動新增反向連結

### 外部連結

```markdown
[顯示文字](URL)
```

---

## 特殊標記

### 草稿標記

若頁面未完成，設置 `status: draft`，並在開頭加：

```markdown
> ⚠️ **草稿** — 此頁面未定稿，內容可能不完整或有待修改。
```

### 過時標記

若頁面內容已過時：

```markdown
> ⚠️ **過時** — 此頁面基於舊版本，請參考 [[新版本]] 了解最新情況。
```

### 衝突標記

若多個來源的敘述相衝突：

```markdown
> ⚠️ **衝突** — 關於此主題，來源 A 說法是 X，來源 B 說法是 Y。詳見...
```

## 版本管理

### 修訂歷史

頁面若有重大修改，在 frontmatter 中遞增 `version` 並在 log 中記錄：

```yaml
---
version: 2  # 從 1 升至 2
---
```

在頁面底部加上修訂記錄：

```markdown
## 修訂歷史

- **v2** (2026-06-18)：加入新概念 X
- **v1** (2026-06-17)：初始版本
```

## Index.md 結構

`wiki/index.md` 是 wiki 的目錄入口，採用**主題優先、組內按來源**的組織方式：

```markdown
# Wiki 目錄

## [主題 1]

- [[頁面 A]] — 來源 1
- [[頁面 B]] — 來源 2 vs 來源 1 對比
- [[頁面 C]] — 綜合

## [主題 2]

- [[頁面 D]] — 來源 3
- [[頁面 E]] — 工作流程

## 待辦

- [ ] [[缺少的概念 1]]
- [ ] [[缺少的概念 2]]
```

---

## Log.md 結構

`wiki/log.md` 記錄 wiki 的變更歷史，採用簡介格式：

```markdown
# 變更日誌

## [2026-06-17] ingest | llm-wiki-karpathy
- 新增摘要頁 3 篇、概念頁 2 篇
- 更新 index：LLM 架構分類

## [2026-06-16] lint | 反向連結修復
- 新增 8 條反向連結
- 標記 2 個孤兒頁

## [2026-06-15] query | LLM 工作流程
- 根據用戶問題合成工作流程頁
```

## Meta.json 結構

`wiki/meta.json` 追蹤每個來源的 ingest 歷史：

```json
{
  "sources": {
    "llm-wiki-karpathy": {
      "filename": "llm-wiki-karpathy.md",
      "first_ingested": "2026-06-17",
      "last_ingested": "2026-06-17",
      "versions": [
        {
          "date": "2026-06-17",
          "pages_created": 3,
          "pages_modified": 0,
          "status": "success"
        }
      ]
    }
  },
  "stats": {
    "total_pages": 5,
    "total_sources": 1,
    "last_lint": "2026-06-17"
  }
}
```

## 品質檢查清單

新增或修改頁面前，檢查：

- [ ] Frontmatter 完整（title、tags、source、date、status）
- [ ] 標題層次清晰（# → ## → ###）
- [ ] 內部連結正確（[[頁面名]]）
- [ ] 至少有 1 個反向連結
- [ ] 若引用外部資源，使用 [](URL) 格式
- [ ] 拼寫和語法正確
- [ ] 頁面長度適中（500-2000 字為佳）
- [ ] 若為草稿，標記 `status: draft`
