# Lint — 維護 Wiki 品質

## 概述

Lint 是 wiki 的定期檢查和修復操作。它掃描 wiki 中的潛在問題（如死連結、孤兒頁、矛盾敘述、缺少交叉參照），並自動修復簡單問題或提出建議。

**目的**：
- 保持 wiki 的連結完整性
- 識別內容矛盾和過時敘述
- 新增反向連結，加強網絡化
- 找出需要補充的內容

**觸發方式**：
- **自動**：每次 ingest 完成後
- **手動**：使用者主動要求

---

## 詳細流程

### 第一步：掃描 Wiki 結構

**目的**：取得 wiki 的完整信息

**方法**：

1. 列出 `second-brain/wiki/` 中所有 `.md` 檔案（除了 `index.md`、`log.md`、特殊檔案）
2. 讀取每個檔案的 frontmatter 和標題
3. 統計頁面總數、標籤分布、來源分布
4. 檢查 meta.json 是否存在和格式是否正確

**進度反饋**：
```
掃描中...
✓ 找到 5 個 wiki 頁面
✓ 讀取 frontmatter...
✓ 統計完成
```

**限制**：最多一次掃描 50 個頁面；若超過，提示稍後分批檢查

---

### 第二步：檢查網路錯誤

**目的**：識別連結問題

**方法**：

1. **死連結檢查**
   - 掃描每個頁面中的 [[連結]]
   - 檢查連結的目標頁面是否存在
   - 若目標頁面不存在，標記為死連結

2. **孤兒頁檢查**
   - 統計每個頁面的入站連結數（有多少其他頁面連到它）
   - 若一個頁面零入站連結，標記為孤兒頁
   - 例外：`index.md`、`log.md` 無須入站連結

3. **未連結檢查**
   - 掃描 index.md，檢查是否列出所有頁面
   - 若有頁面未在 index.md 中提及，標記為「未索引」

**進度反饋**：
```
檢查網路錯誤...
✓ 掃描連結... 15 個
⚠️ 死連結：0 個
⚠️ 孤兒頁：1 個（second-brain/wiki/Draft-Concept.md）
⚠️ 未索引：1 個（second-brain/wiki/Temporary.md）
```

---

### 第三步：檢查內容一致性

**目的**：識別內容問題

**方法**：

1. **過時敘述檢查**
   - 掃描所有頁面，尋找時間相關的敘述
   - 若敘述涉及過去的日期（>6 個月前），標記為「可能過時」
   - 例如：「在 2024 年」、「最新研究表明」（時間不詳）

2. **矛盾標記檢查**
   - 搜尋頁面中的矛盾標記（`⚠️ 衝突`、`# 衝突`）
   - 統計矛盾數量和位置
   - 提示這些內容需人工審查

3. **缺失信息檢查**
   - 掃描是否有 TODO 標記（`[ ]`、`TODO:`、`待補充`）
   - 統計待辦項數量

4. **Frontmatter 完整性檢查**
   - 驗證每個頁面的 frontmatter 是否包含必須欄位
     - `title`
     - `tags`（若為空警告）
     - `source`
     - `date`
     - `status`
   - 若缺失，標記為「frontmatter 不完整」

**進度反饋**：
```
檢查內容一致性...
✓ 掃描所有頁面... 5 個
⚠️ 可能過時：1 個（基於 2023 年的敘述）
⚠️ 矛盾標記：1 個
⚠️ 待辦項：2 個
⚠️ Frontmatter 不完整：0 個
```

---

### 第四步：自動修復

**目的**：對簡單問題進行自動修復

**修復項目**（最多 5 項，超過提示稍後檢查）：

1. **新增反向連結**
   - 對所有孤兒頁，嘗試根據標籤或主題找到相關頁面
   - 在相關頁面的「相關頁面」章節中新增反向連結
   - 修復規則：若兩個頁面的標籤重疊超過 50%，視為相關

   **例子**：
   ```
   頁面 A（標籤：[LLM, 基礎]）
   頁面 B（標籤：[LLM, 進階]）
   → 新增反向連結：[[頁面 B]] 在頁面 A 的「相關頁面」
   ```

2. **修復死連結**
   - 若連結目標頁面更名，嘗試模糊匹配找最相似的頁面
   - 若找到候選，提示使用者確認修復
   - 若無法匹配，保持連結但標記為待確認

3. **補充缺失標籤**
   - 對沒有標籤的頁面，根據內容推斷標籤
   - 根據頁面名稱、frontmatter 中的 `source` 等推斷主題標籤

4. **修正不規範的 Frontmatter**
   - 補充缺失的必須欄位（使用預設值）
   - 標準化日期格式（YYYY-MM-DD）
   - 修正狀態欄位（轉換為 `published` 或 `draft`）

5. **標記重複內容**
   - 掃描頁面標題，找出可能的重複
   - 提議合併或建立消歧義頁面

**進度反饋**：
```
正在自動修復...
✓ 新增 2 條反向連結
✓ 補充 1 個標籤
✓ 修正 frontmatter（1 個頁面）
共修復 3 項
```

---

### 第五步：生成 Lint 報告

**目的**：展示檢查和修復結果

**報告格式**（Markdown 列表）：

```markdown
## Lint 報告 [日期]

### 網路錯誤
- 死連結：0 個
- 孤兒頁：1 個
  - `second-brain/wiki/Draft-Concept.md` — 無入站連結（建議：在 index 中加入或刪除）
- 未索引：1 個
  - `second-brain/wiki/Temporary.md` — 未在 index.md 中列出

### 內容一致性
- 可能過時：1 個
  - `second-brain/wiki/Old-Paper.md` L5 — 基於 2023 年的敘述
- 矛盾標記：1 個
  - `second-brain/wiki/Concept-A.md` L12 — 與 Concept-B.md 敘述相衝
- 待辦項：1 個
  - `second-brain/wiki/Draft-Guide.md` — 5 個待補充事項
- Frontmatter 不完整：0 個

### 自動修復
✓ 成功修復 3 項：
- 新增 2 條反向連結
- 補充 1 個標籤
- 修正 frontmatter（1 個頁面）

❌ 需人工確認 2 項：
- `Dead-Link.md` L8 — 死連結 [[不存在的頁面]] （建議修正為 [[相似頁面]]？）
- `Duplicate-Title.md` vs `Similar-Title.md` — 可能重複（建議合併？）

### 建議
1. 查看 `Draft-Concept.md` 並決定是否要發布或刪除
2. 補充 `Draft-Guide.md` 的待辦項或標記為草稿
3. 檢查 `Old-Paper.md` 是否仍相關
4. 手動確認 2 項修復建議
```

---

### 第六步：請求確認

**方法**：

1. 展示 lint 報告（見上方格式）
2. 分類總結：
   - ✓ 已自動修復
   - ⚠️ 待人工確認
   - ℹ️ 僅供參考

3. 詢問使用者：
   ```
   Lint 完成。找到 N 個問題，已自動修復 M 個。
   
   需人工確認的修復建議：2 項（見上方報告）
   
   要我執行這些修復嗎？
   （回「是」、「是但跳過某項」或「否」）
   ```

4. 根據使用者反饋執行修復

## 修復的邊界情況

### 情況 1：無法判斷正確修復

**症狀**：例如死連結，但無明顯候選頁面

**處理**：
- 標記為「需人工確認」
- 提示使用者：「頁面 X 的連結目標不存在。建議刪除該連結或新增目標頁面。」

### 情況 2：修復會導致內容歧義

**症狀**：例如補充標籤時不確定主題分類

**處理**：
- 不自動修復
- 提示使用者手動確認

### 情況 3：多個修復選項

**症狀**：例如有多個可能的反向連結候選

**處理**：
- 列出所有候選
- 詢問使用者選擇

## Lint 排程

### 建議

- **自動 lint**：每次 ingest 後（無使用者干預）
- **手動 lint**：週期性檢查，例如每周一次
- **全面檢查**：定期全面檢查，例如每月一次

---

## 效能考量

- **最多掃描 50 個頁面**：若超過，提示分批檢查
- **最多自動修復 5 項**：若超過，提示其他問題需人工確認
- **掃描順序**：先網路、後內容（網路錯誤更緊急）

---

## 常見問題

**Q: Lint 會刪除頁面嗎？**  
A: 不會。只標記孤兒頁，提議可能的修復，不自動刪除。

**Q: Lint 可以修改內容嗎？**  
A: 只修改 frontmatter、連結、標籤等結構化信息，不修改正文內容。

**Q: 若 Lint 的修復建議我不同意怎麼辦？**  
A: 可以拒絕。Lint 只是建議，不強制執行。

**Q: Lint 報告會保存在 wiki 中嗎？**  
A: 可選。若使用者同意，會追加到 second-brain/wiki/log.md 中。
